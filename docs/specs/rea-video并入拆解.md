# Spec · rea-video 并入拆解流水线

状态：T1–T5 已实现（PR #9），T6 部分完成 ｜ 优先级：P1

## 为什么要做

现在的拆解能回答「这片子讲了什么」，答不出「这片子是怎么拍的」。而复刻方案最需要的恰恰是后者——**这一镜该去实拍，还是该让模型生成？**

rea-video 做的就是逐镜头判断实拍 / AI 生成 / 3D / 代码渲染，Apache 2.0 可商用，默认全本地零 token。

它还顺带解决一个产品问题：并进来之后，不填 Key 的用户也能拿到一份有价值的报告（字幕 + 分镜 + 拍摄方式），免费层才立得住。

## 目标

- 拆解新增一步「认拍摄方式」，逐镜给出判定和依据
- 判定结果喂进 04/05 的 prompt，让复刻方案知道该拍还是该生成
- 不填 Key 也能跑完并导出

## 不做

- 不引入 VLM（rea-video 的可选增强），先只用本地像素取证
- 不做 3D / 代码渲染的细分，先只分「实拍 / AI 生成 / 图文动画」三类

## 设计

### 插在哪

步骤编号整体后移：04 认拍摄方式、05 整片理解、06 逐段细读、07 拆解包、08 原片分镜。没 Key 时停在 05 之前。

```
01 probe → 02 transcribe → 03 boundaries → [新] 04 forensics → 05 overview → 06 close → 07 pack
                                  ↓                    ↑
                           切点与关键帧 ───────────────┘
```

`console/pipeline.py` 的 `STEP_META` 是个干净的 dict，`_set_step()` 是通用状态写入，加一步结构上很轻。

### 镜号对齐（本 spec 最关键的一条）

rea-video 自己的切镜逻辑和 `03 boundaries` 不一样。**必须让它吃 03 的切点作为输入，输出按 03 的镜号 1:1 索引。** 两套镜号混在一起，合出来的数据没法用，后面所有引用都会错位。

验收时要专门断言：取证结果的条数 == 03 产出的镜头数，且第 i 条对应第 i 个镜头的时间区间。

### 复用关键帧

03 已经抽好关键帧了，不要让 rea-video 再抽一遍——那是整个耗时的大头。帧级取证（噪点、压缩伪影、边缘过渡）直接读 03 的产物；需要整片级特征（帧率一致性）的部分再单独读视频文件。

> **实现时的修正**：这一条做不到。rea-video 的判定主要靠镜头内**连续帧**之间的变化（重复帧比例、帧率转换留下的锐度周期、整帧刚体运动拟合），03 每镜只有一张中间帧，喂不出这些特征。实际省下的是 rea-video 自己的整片逐帧切镜（`build_track` + `detect_shots`）——直接用 03 的镜头表；每镜仍按 480 宽解码一次（带黑边的镜头两次）。8 秒 3 镜样片 6–7 秒。

### 开关

做成可选项「深度取证」，默认对 2 分钟以内的视频开启。纯 CPU 下 71 秒视频实测约 2.5 分钟，不是所有用户都愿意等。

### 结果怎么用

判定写进每一镜的数据，并注入 `console/prompts.py` 的 04/05 prompt，形如「本镜判定：AI 生成（依据：无传感器噪点、边缘过渡异常平滑）」。让模型在出复刻方案时知道这一镜原本就不是拍出来的。

### 许可

rea-video 是干净的 Apache 2.0。并进来要保留它的 LICENSE 和 NOTICE 并声明改动（Apache 2.0 §4）。合并后整体仍受更严的 Hypit 许可约束——**不可做在线多租户，不可收费分发**。

## 风险与未决

- **真机反馈（11-17）**：抖音下载的手机实拍（寿司店探店）6 个镜头全被判成「AI 生成」。平台转码抹掉了传感器噪点、24fps 又像 AI 常用帧率，只看像素分不清。
  已改：实拍 / AI 只有一边明显占优才下结论（`forensics.decide_class`：AI ≥ 0.7 且领先 ≥ 0.4；实拍 ≥ 0.5 且领先），否则标「待确认」，
  prompt 里写明「像素上分不清，请看画面判断」。下一步：让内容拆解的大模型看图后回填每镜判定。
- rea-video 的判定准确率**没有实测过**。T2 完成后要拿一批已知来源的片子（自己拍的 + 已知 AI 生成的）跑一遍，统计误判率，再决定要不要在界面上显示置信度。
- 复用 03 关键帧能省多少时间是估计值，T2 验收时实测前后耗时。
- rea-video 的 OCR extras 会增加依赖体积，可能影响首次下载量，T1 时测一下增量。→ 不需要 OCR；增量只有 opencv-python-headless（几十 MB 的 wheel，T1 时未在真机实测）。
- 已装好运行环境的老用户没有 OpenCV：这一步会显示「已跳过」并提示重新运行一次安装。桌面版向导暂时没有「补装」入口。
- 人脸模型从 GitHub 下载，国内网络可能下不来，会退回 OpenCV 自带的 Haar 检测，人脸相关的判据会弱一些。
- 3D 渲染（cg_3d）、2D 动画归入「图文动画」；细分标签保留在数据里，并一起写进 prompt。
