# Spec · 数据与运行时目录迁移

状态：T1–T5 已实现，待真机回归 ｜ 优先级：P0（阻塞发版）

## 为什么要做

两个问题缠在一起，必须一起解。

**一、瘦包现在是跑不起来的。** `build/main.js` 的 `startServer()` 在 `workbench/runtime/venv/bin/python` 不存在时直接抛错，没有任何安装逻辑。而瘦包按设计不带 runtime，所以当前 main 分支打出的包，用户一启动就是「找不到本地运行环境」。

**二、数据写在应用内部会破坏 macOS 签名。** `workbench/console/config.py` 第 13-18 行把 Key、项目、素材库都挂在 `ROOT` 下：

```python
ROOT = Path(__file__).resolve().parents[1]
ENV_FILE     = ROOT / "console.env"
PROJECTS_DIR = ROOT / "projects"
LIBRARY_DIR  = ROOT / "library"
BATCHES_DIR  = ROOT / "batches"
```

合并后 workbench 装进 `.app/Contents/Resources/`，那里是只读的；就算能写，往签名过的 bundle 里写文件会让签名失效。

## 目标

- 用户数据和运行时都搬到应用外的数据目录
- 首次启动有图形化向导，自动装好运行时
- 老用户的数据能平滑迁过去

## 不做

- 不改拆解逻辑
- 不动界面流程（那是另一份 spec）
- 不实现多数据目录切换，只支持一个

## 设计

### 目录解析

```
DATA_DIR = 环境变量 VIRALREPLICA_DATA_DIR
         ↓ 没有则用平台默认
  macOS   ~/Library/Application Support/ViralReplica
  Windows %LOCALAPPDATA%\ViralReplica
  Linux   ~/.local/share/ViralReplica
```

Electron 启动时把用户选的目录写进 `VIRALREPLICA_DATA_DIR` 再拉起 server.py，所以 Python 侧不需要知道是谁选的。

### 哪些搬、哪些不搬

| 路径 | 去向 | 理由 |
|---|---|---|
| `console.env` | `DATA_DIR/console.env` | 要写 |
| `projects/` | `DATA_DIR/projects/` | 要写 |
| `library/` | `DATA_DIR/library/` | 要写 |
| `batches/` | `DATA_DIR/batches/` | 要写 |
| `runtime/` | `DATA_DIR/runtime/` | 2GB，按需下载 |
| `engine/`、`console/`、`web/` | 留在 Resources | 只读代码 |

`tools/` 下十几个测试本来就在 `patch.object(config, 'PROJECTS_DIR', ...)`，说明这几个变量上游就是设计成可覆盖的，改完不应该炸测试——这是本次改动风险可控的主要依据。

### 首次启动向导

`main.js` 检测 `DATA_DIR/runtime/venv/<平台 python>`：

- 存在 → 照常拉起 server.py
- 不存在 → 开向导窗口（980×660），三步：选目录 → 选识别精度 → 跑安装

安装直接调用工作台自带的 `install.sh` / `install.ps1`，它们已经是幂等的、带 `--mirror` 国内镜像回退、支持 `--model` 选档位。向导只负责把它们包成图形界面并把 stdout 转成进度条，**不要重写安装逻辑**。

`install.sh` 当前用 `ROOT="$PWD"` 定位安装目标，需要加一个 `--target <dir>` 参数。

界面见设计稿的 Setup 画板。

### 老用户迁移

启动时如果发现 `DATA_DIR` 不存在、但旧位置有 `console.env` 或 `projects/`，弹一次确认框，把这四项移过去，移完写一个 `.migrated` 标记。只做一次，失败不阻塞启动，只提示。

## 风险与未决

- **签名后能否拉起下载来的 Python，未实测。** 加固运行时下 `disable-library-validation` 已开（见 `build/assets/entitlements.mac.plist`），但必须等拿到 Apple 证书后真机验证，不能假定通过。
- Windows 侧 `install.ps1` 从未在真实 Windows 上跑过，T3 的验收必须在 Windows 机器上做一遍。
- 向导跑安装需要几分钟到十几分钟，窗口要能关掉重来而不留半截状态——靠 install 脚本自身的幂等性，T5 验收时要专门测一次中断重来。
